# Linux Kernel Release Lifecycle

Linux kernel development is time-based rather than organized around a fixed feature checklist. Changes enter mainline during a merge window, release-candidate kernels expose the integration for testing, and a final release begins the next cycle.

Stable branches receive selected fixes after release, while long-term-support branches remain maintained for longer deployment horizons. Distribution and product kernels build on these upstream lines but may add patches, configuration choices, and their own support commitments.
