# Statement of Work Scope Boundary

A statement of work scope boundary records what a consulting project will deliver, when it will be delivered, how completion will be recognized, and what payment terms apply. It also makes exclusions and client dependencies explicit so a request outside the agreement can be evaluated as additional work rather than silently absorbed.

This boundary protects both parties from different assumptions about an apparently simple project. A pipeline engagement, for example, may include build and staging automation but exclude application refactoring or ongoing on-call support. Written change handling prevents necessary evolution from becoming uncontrolled scope creep.
