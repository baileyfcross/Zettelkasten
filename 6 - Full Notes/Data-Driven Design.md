# Data-Driven Design

Data-driven design stores part definitions, attributes, and values separately from program code, often in a spreadsheet exported to a machine-readable format. The game loads those values over safe defaults at runtime.

This separation lets designers tune and balance content without changing code or waiting for a full rebuild. Hot reloading shortens the [[Designer Loop]], provided the design documents, data, and implemented structures remain synchronized.
