# Applied Cryptography and PKI

Parent topic: [[Cybersecurity Foundations and Defense]]

Applied Cryptography and PKI is the chapter-level topic for turning mathematical security assumptions into usable encryption, authentication, integrity, privacy, and key-management mechanisms. Full Notes link to one of the focused child topics rather than directly to this chapter tag.

## Overview Chapter

Cryptographic systems begin with a distinction between construction and attack. [[Classical Ciphers and Cryptanalysis]] makes that relationship visible in small, understandable mechanisms. A Caesar cipher shifts each symbol through a finite alphabet, a Vigenere cipher varies those shifts with a repeating keyword, and a Hill cipher applies matrix arithmetic to blocks of symbols. Their weaknesses expose reusable lessons: a small key space permits exhaustive search, repeated key structure enables frequency-based recovery, and a linear transformation can reveal its key under a known-plaintext attack. Cryptanalysis is therefore not separate from design; it tests whether an intended security property survives the information available to an adversary.

Secure systems also need values and digests that cannot be predicted or manipulated cheaply. [[Cryptographic Randomness and Hashing]] separates deterministic pseudorandom generation from physical entropy and asks whether an observer can predict the next output or recover earlier and later outputs after state compromise. The same topic treats a hash as a fixed-size digest whose usefulness depends on resistance to preimage, second-preimage, and collision search. Salts make repeated password inputs distinct, while message authentication codes add a secret key so that an integrity value also demonstrates possession of shared key material. Attacks such as collision search and length extension show why a digest algorithm and the way it is composed must be evaluated together.

[[Symmetric Encryption Algorithms and Modes]] covers efficient confidentiality under a shared secret. DES illustrates a 64-bit block cipher whose 56-bit effective key became vulnerable to exhaustive search, while Triple DES extends the older construction by applying it repeatedly. AES supplies the newer standard with larger key choices. A block cipher alone handles only one fixed-size block, so a mode defines how blocks, counters, feedback, and initialization values are combined across a message. ECB treats blocks independently; CBC chains them; CFB and OFB turn feedback into stream-like processing; CTR encrypts successive counter values; and GCM couples counter-based encryption with an authentication result. Correct key and initialization handling remain part of the encryption design.

Shared secrets do not solve every distribution or identity problem. [[Public-Key Cryptosystems and Digital Identity]] uses related public and private keys so a sender can protect material for a recipient without first transporting the recipient's private key. RSA bases its construction on arithmetic involving a product of large primes, ElGamal works in a cyclic group and creates a shared value during encryption, and Merkle-Hellman demonstrates a trapdoor-knapsack construction whose original form was later broken. Practical communication often uses a hybrid arrangement: public-key operations protect a session key while symmetric encryption carries the larger payload. Certificates and public key infrastructure bind keys to identities, digital signatures bind a signer to message content, and interactive identification protocols let a prover answer verifier challenges without simply disclosing the underlying secret.

Some applications require useful work without exposing the underlying plaintext. [[Privacy-Preserving Encryption]] collects two such approaches. Homomorphic encryption evaluates supported operations on ciphertext and returns an encrypted result corresponding to a plaintext computation. Partial, somewhat, and fully homomorphic schemes differ in which operations they support and how often those operations may be composed. Noise accumulation can eventually prevent correct decryption, while bootstrapping refreshes a ciphertext so evaluation can continue. Searchable encryption narrows the goal to queries over encrypted documents: an encrypted index and a trapdoor derived from a query let a server locate matching encrypted records while query isolation limits what that server learns.

The quantum boundary produces both new communication mechanisms and pressure on existing public-key assumptions. [[Quantum and Post-Quantum Cryptography]] explains how quantum key distribution encodes candidate key bits in quantum states, reconciles compatible measurement bases over a classical channel, checks an error sample for interception, and applies privacy amplification before retaining a key. BB84 is the central example. Post-quantum work takes a different route by building classical algorithms from problems expected to resist quantum attacks. Lattice problems such as finding a shortest vector motivate systems such as NTRU, whose messages and keys are represented through low-coefficient polynomials. A hybrid NTRU-and-AES design can protect compact key material with the lattice-based scheme and use symmetric encryption for the message body.

Finally, secure primitives must be exposed through implementation boundaries that discourage accidental reinvention. [[Java Platform Cryptography and Security]] describes the Java Cryptography Architecture as a provider-based framework. Applications request an algorithm through engine classes such as `Cipher`, `MessageDigest`, `Signature`, and `KeyPairGenerator`, while a selected provider supplies the implementation. The Java Cryptography Extension supplies encryption and key-agreement facilities, Jakarta Security brings portable authentication mechanisms into enterprise applications, and OpenSSL can generate or convert keys and certificates used by Java programs. These interfaces do not eliminate design responsibility, but they separate algorithm requests, implementations, keys, and data flows so standardized components can be integrated and maintained.

Together, the child topics form an applied stack. Mathematical assumptions and cryptanalysis determine what a primitive can promise; random generators and hashes supply unpredictable or one-way building blocks; symmetric and public-key schemes provide confidentiality and identity mechanisms; privacy-preserving and quantum-era constructions extend what can be protected; and the Java platform turns those mechanisms into callable services. Public key infrastructure sits across the stack by managing the certificates, authorities, and key associations needed to make cryptographic evidence meaningful in an operating system or network rather than only in an equation.
