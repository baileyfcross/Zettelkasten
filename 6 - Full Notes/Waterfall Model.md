# Waterfall Model

The Waterfall model moves through conceptual development, requirements analysis, architectural and detailed design, coding and debugging, system testing, release, and maintenance as successive phases. Each phase is expected to finish before the next begins, with documents and approval marking the transition.

Its central weakness is the assumption that an earlier phase can be completed correctly without feedback from later implementation and testing. When requirements or understanding change, the model provides little natural way to move backward, so an early error can propagate through increasingly expensive downstream work.
