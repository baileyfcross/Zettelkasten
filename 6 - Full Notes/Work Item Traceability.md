# Work Item Traceability

Work item traceability links epics, features, backlog items, tasks, code changes, builds, tests, and releases into a navigable delivery history. It allows a team to follow a need downward into implementation evidence or a change upward to its intended value.

Traceability is strongest when relationships have consistent meanings. Excessive or ambiguous links make the graph dense without answering whether a requirement was implemented and verified.
