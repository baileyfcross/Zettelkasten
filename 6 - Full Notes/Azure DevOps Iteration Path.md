# Azure DevOps Iteration Path

An Azure DevOps iteration path places a work item in a time-based planning hierarchy such as a release, sprint, or milestone. It lets backlog and board views distinguish current, future, and completed planning intervals.

The path expresses scheduling intent rather than an immutable delivery promise. Movement between iterations should remain visible so the team can learn from recurring carryover or unrealistic capacity assumptions.
