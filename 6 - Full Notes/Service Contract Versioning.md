# Service Contract Versioning

Service contract versioning lets a service evolve without forcing every consumer to deploy at the same moment. A published API description states routes, message shapes, and expected behavior; an incompatible change can be introduced under a new version while older versions remain available for a transition. The book's microservice example uses versioned Swagger definitions to make the boundary and planned compatibility period visible to other teams.
