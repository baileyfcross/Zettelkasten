# Code-and-Fix Model

Code-and-fix development begins with only a rough understanding of a problem, then cycles through writing, running, observing a failure, and applying the next apparent repair. It minimizes formal planning and can produce a disposable result quickly for a very small, short-lived effort.

The same immediacy makes it dangerous for maintained software. Without deliberate requirements, architecture, configuration management, review, and systematic testing, local fixes accumulate into an idiosyncratic design whose behavior and future change cost are hard to predict.
