# Object-Oriented Middleware

Object-oriented middleware allows one application to invoke or reuse code represented as an object supplied by another application or service. The integration boundary is a callable behavior and its interface rather than a shared database or queued message.

This can provide direct reuse but can also couple participants to interface, execution, and failure assumptions. The book distinguishes it from [[Message-Oriented Middleware]] and [[Data-Oriented Middleware]] as a separate integration style.
