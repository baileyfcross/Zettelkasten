# Object-Oriented Analysis

Object-oriented analysis studies a problem domain to identify its essential features, candidate objects, behaviors, and relationships without committing to implementation details. Its result is a conceptual account of what the system must represent and accomplish.

Problem statements, feature lists, user stories, scenarios, use cases, and preliminary class diagrams provide evidence for that model. Analysis is iterative because prototypes and stakeholder feedback reveal missing requirements, but it should remain distinct enough from design that a current implementation idea does not redefine the problem unnoticed.
