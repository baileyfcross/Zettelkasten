## Overview Chapter

Java programming is built around a separation between source code, a portable class-file representation, and execution by a virtual machine. That separation shapes more than deployment. It determines how projects are organized, how types are checked, how objects occupy memory, how libraries expose reusable operations, and how running programs can be inspected. The language and the platform therefore form one system: syntax expresses intent, the compiler checks and translates it, the runtime manages execution and memory, and the standard libraries connect programs to files, databases, networks, user interfaces, and concurrent work.

### Platform and project boundaries

[[Java Platform Runtime and Project Structure]] begins with the path from a source file to bytecode and from bytecode to execution on an operating-system-specific Java Virtual Machine. The JDK supplies the compiler and development tools, while a runtime executes the resulting classes. OpenJDK distributions package compatible implementations of that platform. Environment configuration such as `JAVA_HOME`, command-line compilation and launching, source-file launch mode, and JShell provide progressively different ways to move from a small experiment to a repeatable build.

As code grows, packages establish namespaces and access boundaries, JAR files bundle compiled artifacts, and the classpath identifies where dependencies can be found. An uncontrolled classpath can produce version conflicts commonly described as JAR hell. The module system adds explicit descriptors and directives for dependencies and exported packages, allowing a project to state which parts are required and which parts are visible. Maven then supplies a conventional project layout and lifecycle so source code, tests, dependencies, and generated artifacts occupy predictable places. These mechanisms make structure part of correctness: the runtime must be able to locate the same definitions that the compiler used.

### Declaring behavior and representing values

[[Java Classes Interfaces and Type Declarations]] describes the principal forms used to model a program. Classes combine fields, constructors, and methods; objects are instances whose state is accessed through instance members, while static members belong to the class. Overloading selects among declarations with different parameter lists, varargs accept a variable number of arguments, and constructor chaining centralizes initialization. Encapsulation uses access control and accessor methods to keep representation choices behind an intentional interface.

Inheritance and overriding allow a derived class to refine inherited behavior. Abstract classes can retain shared state and partial implementation, whereas interfaces define contracts that unrelated classes can implement. Default interface methods extend a contract with behavior, but must still fit Java's rules for resolving inherited implementations. Enums model a fixed set of named instances, records provide a compact form for data-centered types, sealed hierarchies restrict which declarations may extend or implement a type, and annotations attach metadata that tools or runtimes can interpret. Together these forms let the programmer choose how open, constrained, stateful, or data-oriented a model should be.

Those declarations operate on the values in [[Java Values Strings and Core Types]]. Primitive values and object references have different representations, yet Java passes both kinds of arguments by value: a copied reference may still designate the same object. Local execution uses stack frames while objects and arrays normally live on the heap. Widening and narrowing conversions govern numeric movement, wrapper types bridge primitive values into object-oriented APIs, and boxing or unboxing performs that bridge automatically in many expressions. Arrays have a fixed length and element type; a `null` reference designates no object and must be handled before dereference.

Strings add their own important rules. They are immutable objects, may be shared through the string pool, and require content equality rather than reference identity when the text is what matters. Escape sequences, text blocks, formatting, and concatenation provide different ways to construct readable text. Local-variable type inference lets the compiler infer a declared local type from its initializer without weakening static typing, and the diamond operator reduces repeated generic arguments when the surrounding declaration already supplies enough information.

### Arrays, object construction, and forms of reuse

[[Java Arrays and Elementary Algorithms]] follows fixed-size storage from creation through use. Array elements receive defaults, indexes begin at zero, and each row of a multidimensional array is itself an array with its own length. That representation permits rectangular or ragged structures. Linear and binary search demonstrate different requirements for finding a value; bubble sort demonstrates repeated indexed comparison and swapping; and matrix multiplication combines one input row with one input column for each result cell. Cloning copies an array shallowly, while `System.arraycopy` transfers a selected range into another array.

[[Java Object Construction and Class Members]] focuses on what happens inside a class boundary. Instance and static fields differ in ownership, local variables differ from fields in scope and default initialization, and instance or static initializer blocks place shared setup in source order. Constructors establish each object's state, including blank final fields, while methods receive copied argument values and may be overloaded or declared with a final varargs parameter. Returning `this` permits method-call chaining, recursion gives each self-call its own stack frame, and a utility class groups operations that require no per-object state.

[[Java Inheritance Composition and Object Contracts]] distinguishes several relationships that are easy to conflate. Class inheritance models an is-a relationship and late binding selects an override from the runtime object; upcasting restricts the visible interface, while a checked downcast attempts to regain a subtype. Abstract classes and interfaces state incomplete behavior in different forms, and interfaces can extend several interfaces or own static utility methods. Every class ultimately inherits from Object, whose equality, hash, string, and cloning contracts shape collections and diagnostics. Composition instead models has-a structure, and forwarding lets a wrapper add behavior without depending on a superclass's internal calls.

[[Java Nested Types and Package Organization]] moves from lexical enclosure to distribution. A static nested class has no implicit outer object, while an inner class does; local and anonymous classes place an implementation inside a block or expression and can capture effectively final values. Package declarations establish qualified namespaces and directory structure, ordinary and static imports shorten selected names, and access levels determine which package or subclass code may reach a member. JAR files preserve packaged class directories in one archive, and the classpath tells a nonmodular runtime where those directories and archives can be found.

### Numeric, textual, and system-level utilities

[[Java Numeric Utilities and Arbitrary Precision]] separates primitive arithmetic from library-supported calculations. Math supplies named constants, trigonometric functions that consume radians, common numerical helpers, and a pseudorandom double that can be scaled into a bounded integer interval. BigDecimal represents immutable arbitrary-precision decimal values with explicit scale and rounding, while BigInteger represents immutable integers beyond primitive ranges. These types make the required number representation part of the operation instead of assuming binary floating point or fixed-width integer behavior fits every domain.

[[Java String Processing and Mutable Text]] contrasts shared immutable values with an explicitly mutable buffer. Strings can be constructed from literals or character arrays, compared by content, interned in a pool, and inspected or transformed through indexed and search methods. Transformations return new Strings. StringBuffer instead grows an internal character array and changes its own contents through append, insert, delete, or reverse. A character-by-character word counter shows how a small amount of state can recognize transitions into words, while buffer reversal shows the difference between reversing characters and reorganizing higher-level tokens.

[[Java System Runtime Services]] collects the static facilities that connect a program to its execution environment. Bulk array copying, epoch-based wall-clock time, high-resolution elapsed timing, best-effort garbage-collection requests, and a portable line separator are available without constructing a System object. Standard input, output, and error remain distinct streams that shells or Java code can redirect, and formatted output maps arguments through explicit conversion specifiers. System properties expose runtime key-value data, Properties can persist application configuration, and `System.exit` begins virtual-machine shutdown with a status for the calling environment.

### Collections, time, operators, and control

[[Java Collections and Date-Time]] organizes values beyond fixed arrays. Lists preserve positional sequences, sets enforce uniqueness according to equality and hash behavior, maps associate keys with values, and queues or deques express ordered insertion and removal. Factory methods can create collections whose contents cannot be modified through their returned interface. Iterators and enhanced traversal expose contents without forcing every collection to share one physical layout. Correct equality, hash codes, and ordering are essential because collections rely on those contracts to locate, deduplicate, and sort elements. The date-time API separates local calendar values from instants and time-zone-aware values, while formatters translate between typed temporal values and text.

[[Java Operators and Pattern Matching]] covers the expression-level rules that transform those values. Assignment and compound assignment update variables; arithmetic includes integer division and remainder; relational and equality operators compare values or references according to their operands. Short-circuit Boolean operators may skip their right-hand expression, while bitwise and shift operators work on integral bit patterns. The conditional operator chooses one of two expressions, and precedence determines grouping when parentheses do not make the intended order explicit. Type patterns for `instanceof`, records, and primitive values combine a successful test with access to a more specific representation, reducing the distance between recognizing a shape and using its components.

Statements in [[Java Control Flow and Exceptions]] decide which expressions run. `if` and `else` express conditional branches. Classic `switch` supports statement-oriented case selection, while switch expressions return values and pattern matching can select behavior by type and structure. `for`, enhanced-for, `while`, and `do-while` loops cover counted iteration, collection traversal, precondition repetition, and postcondition repetition. `break`, `continue`, and `return` transfer control out of their ordinary sequence.

Exceptions provide a second control path for failures. Checked exceptions must be caught or declared, while unchecked exceptions can propagate without a declaration. `try`, `catch`, and `finally` separate protected work, recovery, and cleanup; try-with-resources gives resources a structured closing boundary. Wrapping an exception can add domain context while retaining its cause, and a custom exception can make a failure meaningful to callers. The exception hierarchy is therefore both a taxonomy of failures and a contract about which failures an operation expects its callers to address.

### Functional pipelines and concurrent work

[[Java Streams and Functional Processing]] turns behavior into values through functional interfaces, lambda expressions, and method references. A stream pipeline begins with a source, adds intermediate operations, and ends with a terminal operation. Pipelines are lazy: intermediate work is driven by the terminal demand, and a stream is single-use once consumed. Primitive stream specializations avoid unnecessary boxing for common numeric operations; finite and infinite streams differ in whether a terminal operation can complete without an explicit bound. `Optional` represents a result that may be absent without using a bare `null` as the return contract.

Filtering selects elements, mapping transforms them, and flat mapping replaces one input with zero or more outputs while flattening the result. Selection and slicing constrain which elements continue, and collection or reduction combines a stream into a result. Parallel streams can divide compatible work, but they do not make every pipeline faster or every side effect safe. Java 23 gatherers generalize stateful intermediate processing by defining how elements are initialized, integrated, combined where appropriate, and finished. The common lesson is that pipeline structure should make data dependencies explicit before execution strategy is changed.

[[Java Concurrency and Reactive Streams]] addresses operations that overlap in time. Threads execute `Runnable` work and move through lifecycle states; coordination operations manage completion and interruption. Synchronization protects shared mutable state from races, while executors separate task submission from the threads that carry tasks. `Future` represents a pending result, and `CompletableFuture` composes dependent asynchronous stages. Virtual threads reduce the cost of maintaining many blocking tasks, and structured concurrency treats related concurrent subtasks as one bounded operation whose success, failure, and cancellation can be managed together.

Reactive programming reverses a simple pull loop into a protocol between publishers and subscribers. A subscription carries demand so backpressure prevents a producer from overwhelming a consumer. A processor is both subscriber and publisher, and `SubmissionPublisher` supplies a standard implementation for submitting items to subscribers. The Reactive Streams Technology Compatibility Kit tests implementations against the protocol, while Reactor's `Flux` and `Mono` represent multi-value and zero-or-one-value asynchronous sequences. These abstractions change coordination, but they do not remove the need to define ownership, failure propagation, cancellation, and capacity.

### Evidence, interfaces, and stored data

[[Java Diagnostics Testing and Documentation]] supplies evidence about both code and running processes. Logging records events at levels and routes them through handlers and formatters; SLF4J provides a facade and Logback provides a configurable implementation. Assertions state conditions intended for development checks. IDE breakpoints pause execution at selected locations, while `jps`, `jcmd`, JConsole, Mission Control, Flight Recorder, and the Process API expose progressively richer views of local Java processes, commands, metrics, and recorded runtime events.

Testing follows Maven's separate test-source layout and JUnit's lifecycle and assertion model. Fakes and stubs provide controlled substitutes, while mocks can verify a collaboration with a dependency. These test doubles answer different questions and should not be treated as proof that the replaced integration works. Javadoc turns structured source comments into navigable API documentation, connecting an implementation to the contract presented to its users.

Programs meet people and other systems through [[Java Application Interaction and Internationalization]]. Standard input can be read directly or through `Scanner` and `Console` conveniences. Swing applications coordinate components and layout on an event-dispatch thread. Locales and resource bundles move language- and region-specific text out of hard-coded control flow. For network interaction, the JDK simple web server can expose files during development, `SimpleFileServer` can be embedded, and servlet containers manage request lifecycles. JavaServer Pages and tag libraries generate server-side views, while a web archive packages an application for deployment to a container such as Tomcat.

[[Java File IO Serialization and Persistence]] follows information across storage boundaries. `File` is the older pathname abstraction, while `Path` and `Files` support modern creation, traversal, copying, moving, deletion, temporary resources, and file-tree operations. Character readers and writers handle text; byte streams handle binary content; buffering reduces repeated low-level operations. Try-with-resources ensures closeable resources are released even when an operation fails.

Native object serialization writes a Java-specific object representation and carries compatibility and safety constraints. XML and JSON serializers instead map objects to textual interchange formats, and ImageIO handles supported media formats. JDBC connects Java code to a relational database through connections, statements, result sets, and explicit resource management. Each persistence choice defines a contract outside the live object graph, so format compatibility and cleanup are as important as the in-memory class design.

### Managed memory as a runtime responsibility

[[Java Garbage Collection and Memory Management]] completes the path from object creation to reclamation. An object becomes collectible when it is no longer strongly reachable, but the time of reclamation is controlled by the runtime. Generational or region-based heap organization exploits common object-lifetime patterns. Minor, major, and full collections describe different scopes of work, while Serial, Parallel, G1, ZGC, Shenandoah, and Epsilon embody different goals or behaviors. Collector selection therefore depends on desired throughput, pause times, available memory, and the workload rather than on one universally best algorithm.

Runtime heap statistics and garbage-collection logging make those tradeoffs observable. Finalization is unsuitable as a dependable resource-management mechanism, while `Cleaner` offers a controlled fallback that still should not replace explicit closing. Soft, weak, and phantom references provide different relationships to reachability, and reference queues let a program observe when the runtime changes those relationships. `OutOfMemoryError` marks a failure to satisfy an allocation, but its cause may involve heap exhaustion, metadata, native resources, or an unsuitable configuration. Automatic memory management removes explicit deallocation from ordinary Java code; it does not remove limits or the need to understand object lifetime.

### Release evolution as an engineering constraint

[[Java Release and Feature Lifecycle]] places individual language and platform changes in the cadence that delivers them. Java's time-based releases separate the arrival of new features from a vendor's decision to maintain a release for a longer period. Preview features are complete enough for real feedback but can still change, while incubator modules expose provisional APIs without presenting them as permanent platform contracts. An application that tries either category must use the corresponding compiler or launcher options and should isolate the experiment from code that requires a stable baseline.

That lifecycle makes migration an evidence-gathering exercise. A team aligns its compiler, runtime, build plugins, test runners, and deployment image; audits removed, deprecated, or encapsulated dependencies; and then tests behavior on the target JDK. A long-term-support migration can collect several years of language, API, collector, and launcher changes at once, so a small feature sandbox is useful before production code adopts a new construct. Port removal and APIs deprecated for removal also show why “still compiles today” is weaker than an explicit compatibility plan.

### Data-oriented declarations and pattern construction

[[Java Records Patterns and Construction]] connects records' concise data representation to the language features that inspect and initialize structured values. A compact constructor validates or normalizes the canonical component list without restating every assignment. The generated component accessors, equality, and hash code make records useful as return values and compound map keys, provided mutable components are not mistaken for deep immutability. Equality is value-oriented, but ordering remains a separate policy supplied by a comparator or component comparison.

Record patterns reverse construction by deconstructing components, and nested patterns can follow a nested record graph in one test. Type inference reduces repetition for generic record patterns. Within a pattern switch, guarded cases add conditions after a structural match, dominance rules reject cases hidden by broader patterns, and exhaustiveness checks require a complete result. Unnamed variables and patterns explicitly discard values that must be present syntactically but are irrelevant semantically. Java 25's flexible constructor bodies similarly make intent visible by allowing argument checks and preparation before `super(...)` or `this(...)`, without granting unrestricted access to an incompletely initialized object.

### Ordered collections and stateful stream transformations

[[Java Collection and Stream Evolution]] extends the collection framework's ordering vocabulary and the Stream API's transformation vocabulary. Sequenced collection, set, and map interfaces provide uniform access to first and last elements and to a reversed view. The reversed form is a live view rather than an unrelated copy, so changes and encounter order must be understood through the backing collection. These interfaces let an API promise order without requiring callers to depend on one concrete list, set, or map implementation.

Stream evolution includes terminal conveniences such as `toList`, multi-output mapping through `mapMulti`, and a teeing collector that sends the same input through two collectors before merging their results. Gatherers go further by supporting stateful intermediate stages. Fixed and sliding windows group neighboring elements differently; fold emits one accumulated result, while scan emits each intermediate accumulation. A concurrent mapping gatherer uses bounded virtual-thread concurrency for blocking transformations. A custom gatherer must make its initializer, integrator, optional combiner, and finisher agree about state ownership, result emission, and whether parallel execution is valid.

### Structured tasks and scoped context

[[Java Structured Concurrency and Scoped Context]] treats concurrent work as a hierarchy with visible lifetime. A structured task scope forks related subtasks and joins them under a policy rather than leaving independent futures scattered across control flow. One joiner can require every task to succeed, another can return the first successful result, and a custom joiner can encode domain rules such as accepting a minimum number of offers. Cancellation propagates to work that is no longer needed, timeouts bound waiting, and nested scopes keep secondary tasks inside the lifetime of the task that created them.

Scoped values complement that task structure with one-way contextual data. A binding is established for a bounded operation and is visible to called code without being passed through every signature. Child tasks can inherit the binding, but code cannot mutate it as shared thread-local state. This makes request identifiers, configuration, or security context easier to reason about in virtual-thread and structured-concurrency code. The contrast with `ThreadLocal` is therefore not just syntax: scoped context has a lexical lifetime and immutable binding, while thread-local data is associated with a thread and requires explicit cleanup when threads are reused.

### Native boundaries, class files, and vector computation

[[Java Low-Level Platform and Native Performance]] covers facilities that deliberately operate below ordinary object-oriented application code. The Foreign Function and Memory API represents native memory with bounded segments, controls lifetime through arenas, discovers symbols, describes native signatures, and creates downcalls or upcalls through a linker. These abstractions replace many direct uses of unsafe memory access with explicit spatial and temporal boundaries. They reduce accidental misuse but do not make a native function's own contract, alignment, or ownership requirements disappear.

The Class-File API similarly offers a supported model for reading and building class files instead of requiring each bytecode tool to maintain its own parser for every class-file version. At the computational level, the Vector API expresses operations over a hardware-appropriate vector species. The same lane-wise computation can cover a bulk region with SIMD instructions and handle the tail that does not fill a complete vector. Auto-vectorization can optimize some ordinary loops, while the explicit API states the intended vector shape when predictable transformation matters. Both the Vector API's incubator status and native integration's platform dependence belong in the design decision.

### Portable SIMD and single-core optimization

[[Java SIMD and Single-Core Optimization]] develops that vector-computation boundary into a complete optimization method. A preferred vector species lets one algorithm adapt its lane count to the available hardware, while masks preserve correctness for partial tails and conditional lanes. Shuffles, blends, slices, compression, expansion, gathers, scatters, and zip/unzip transformations determine how values move between lanes and memory. These operations can replace branches or reorganize data, but irregular access and cross-lane dependencies may cost more than the parallel work saves.

Reductions and scans illustrate the difference between independent lane-wise arithmetic and operations whose results depend on earlier values. Partial accumulators, tree-shaped combinations, transposed batches, and explicit carry propagation can expose parallel work when associativity and data layout permit it. Floating-point algorithms add another constraint because regrouping additions changes rounding. Pairwise and compensated summation can improve accuracy, yet a vectorized result may still vary with vector length and summation order.

The same chapter treats optimization as a measured interaction among algorithms, the JIT compiler, and the processor. Branchless execution, residue-class lookahead, memoization, structure-of-arrays layouts, recurrence reformulation, and rejection compaction can create SIMD-friendly work. Loop unrolling and independent accumulators may raise instruction-level parallelism, but also increase register pressure or structural hazards. Warmup, generated-assembly inspection, and comparison against a scalar baseline are therefore part of the method: explicit vectors are useful when measured behavior supports them, not a guarantee that every rewritten loop is faster.

### From a single source file to documented programs

[[Java Source Launch and Documentation]] lowers ceremony at two boundaries: starting a program and explaining an API. A compact source file can omit an explicit enclosing class, and an instance main method can omit the traditional static entry-point form. Main-method selection still follows defined rules when several candidate signatures exist. The source launcher can compile an initial file in memory and, with multi-file launch support, locate referenced source files without a visible separate compilation step. A shebang line can make a source file convenient to invoke in script-like environments, while normal packages and build tooling remain appropriate once the program needs reproducible artifacts.

Module import declarations make the exported packages of a module available through one declaration, including in JShell, but duplicate simple names still require disambiguation. Compact programs also receive convenient access to `java.base`, and the `IO` helper reduces console boilerplate. Documentation evolved alongside source form: `{@snippet}` embeds structured examples, and Markdown documentation comments express headings, lists, links, and fenced code through `///` lines. Helpful null-pointer messages serve a related explanatory goal at runtime by identifying which part of an expression was null rather than reporting only the exception type.

### Standard APIs that strengthen common boundaries

[[Java Platform API Evolution]] collects smaller additions whose value appears at concrete application boundaries. Core reflection was reimplemented over method handles so reflective behavior rests on the JVM's maintained invocation mechanisms. An address-resolver service-provider interface permits alternative name-resolution strategies. UTF-8 becoming the default charset reduces dependence on a machine's historical locale, although protocols and stored formats should still state their encoding when interoperability requires it.

Arithmetic additions expose exact operations that report overflow, ceiling division and modulus with defined rounding direction, and numeric clamping to bounds. A presized `HashMap` factory can avoid resize work when an expected entry count is known. String APIs can split while retaining delimiters and search within bounded ranges. The HTTP client can participate in try-with-resources, select among supported protocol versions, and route response bodies through handlers. Stable values provide one-time lazy initialization that the runtime can optimize, while the Java 26 outlook's lazy constants refine that direction. Restrictions on final-field mutation pursue the matching invariant from the other side: code should not use deep reflection to turn a value declared final into mutable state.

Across these topics, Java's central pattern is the use of explicit contracts at boundaries. Types constrain values, packages and modules constrain visibility, exceptions describe failure, streams describe transformations, subscriptions describe demand, tests describe expected behavior, formats describe persisted data, and runtime tools describe actual execution. The platform is most coherent when those contracts agree: a project builds with the dependencies it declares, an object obeys the equality rules its collection expects, a concurrent task propagates failure within its lifetime, and an external representation can be read by the code that receives it. Java's portability and managed runtime are therefore foundations for disciplined structure, not substitutes for it.
