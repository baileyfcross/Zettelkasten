# Requirements-to-Code Workflow

A requirements-to-code workflow carries a requested capability through clarification, architecture and context discovery, task decomposition, implementation, and validation. Language models can help translate across these stages, but each handoff can lose constraints or introduce assumptions.

Traceability connects generated files and tests back to accepted requirements. The workflow should surface ambiguity early, retrieve repository evidence, generate changes incrementally, and require executable acceptance results before declaring completion.
