# Theory of Computation

Parent topic: [[Computer Science]]

## Overview Chapter

The theory of computation begins by separating valid reasoning from the particular subject matter being discussed. [[Formal Logic]] treats propositions as truth-valued objects and combines them through negation, conjunction, disjunction, conditionals, and quantifiers. Truth tables make small propositional arguments mechanically checkable, while Boolean equivalences allow formulas to be transformed without changing their meanings. The same algebra connects logic to hardware: a combinatorial circuit realizes a proposition through gates, and simplifying the proposition can simplify the circuit. Predicate logic adds properties, relations, domains of discourse, and quantified variables, making it possible to express claims about every object or the existence of some witness.

Correct reasoning becomes a reusable mathematical method in [[Proof Methods and Recursive Definitions]]. A valid argument preserves truth from premises to a conclusion, and rules such as modus ponens and modus tollens can be chained into formal proofs. Direct proof starts from a hypothesis and derives its consequence; contrapositive and contradiction reorganize the logical task when the direct route is opaque. Induction handles an unbounded family of finite cases by anchoring a base case and proving that established cases force later ones. That structure closely follows recursion: a recursive definition or algorithm resolves a problem through smaller instances and must eventually reach a base case. Inductive reasoning therefore provides both mathematical results and correctness arguments for recursive computation.

[[Set Theory and Relations]] supplies the objects over which those arguments operate. A set is determined by its members, equality is proved through containment in both directions, and union, intersection, difference, and power set build new collections. Cartesian products turn elements into ordered tuples, allowing a binary relation to be represented as a set of pairs. Properties such as reflexivity, symmetry, antisymmetry, and transitivity distinguish equivalence relations from orders. Transitive closure then converts a one-step relation into reachability through an arbitrary finite sequence, a pattern that reappears in graphs, automata, derivations, and program execution.

Mappings and sizes are developed in [[Functions Cardinality and Relational Data]]. A function assigns one output to every input in its domain; injective, surjective, and bijective functions describe whether inputs collide, codomain values are reached, or two sets can be paired exactly. Bijections extend the meaning of size beyond finite counting. Some infinite sets, including the natural numbers and rationals, can be enumerated, while diagonalization proves that real-number-like collections and power sets cannot be exhausted by a natural-number list. The same language has a practical application in relational databases, where tables are relations, rows are tuples, primary keys enforce unique identification, and SQL operations select, project, update, and join structured data.

The study of symbolic computation becomes explicit in [[Regular Languages and Finite Automata]]. An alphabet supplies symbols, strings arrange them in finite sequences, and a formal language selects a set of strings. Regular expressions generate languages using alternatives, concatenation, and Kleene repetition. Finite-state automata recognize languages by carrying only one of finitely many states as they read input. Nondeterministic machines may follow several possible paths or move without consuming a symbol, but subset construction turns their possible-state sets into deterministic states. Regular expressions and finite automata therefore describe the same class of languages. The pumping lemma exposes the class's limit: a sufficiently long accepted string must revisit a state and contain a repeatable segment, so languages requiring unbounded matching can fail to be regular.

[[Context-Free Languages and Parsing]] adds recursive grammatical structure and a stack-like form of memory. A context-free grammar generates strings by replacing a nonterminal with a prescribed string of terminals and nonterminals. Derivations record those replacements, while parse trees expose their hierarchical structure without depending on the order of independent steps. Ambiguous grammars give one string more than one structure, which is unacceptable when structure determines a program's meaning. BNF makes grammar rules convenient for language specifications; LL(1) parsing predicts a left derivation from the top down, while LR(1) parsing uses shifts and reductions to reconstruct a right derivation from the bottom up. Pushdown automata recognize exactly the context-free languages by adding a stack to finite control, but their own pumping lemma shows that even stack-based grammar has limits.

Those limits lead to [[Turing Machines and Computability]]. A Turing machine combines finite control with a tape that can supply as much storage as a particular computation requires. Its transition rules read and write one cell, move left or right, and change state. This simple device can compute string functions, decide languages by always halting with yes or no, or accept languages by halting only on members. Acceptable languages are the recursively enumerable languages and coincide with the languages generated by unrestricted grammars; decidable languages are the recursive languages whose membership and nonmembership can both be effectively recognized. Universal machines strengthen this account by interpreting encoded machines as data and simulating their executions.

The resulting framework explains both the reach and the boundary of algorithms. The Church–Turing thesis identifies effective computation with what a Turing machine can perform, supported by the mutual simulation of programming languages, multitape variants, grammars, and other models. Universality does not mean that every precisely stated question is computable. The halting problem uses encoded self-reference to prove that no algorithm can correctly decide for every program and input whether execution will stop. Related questions about universal termination or program equivalence inherit this computational unsolvability. Theory of computation therefore unifies logic, proof, discrete structure, language, machine, and limit: it shows how finite descriptions can generate or recognize infinite behavior, and it also proves where every such method must fail.
