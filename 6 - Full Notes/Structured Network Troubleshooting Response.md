# Structured Network Troubleshooting Response

A structured network troubleshooting response separates five elements: the operational finding, confirmed evidence, a qualified likely cause, specific next checks, and remaining unknowns. This shape lets an engineer scan the answer quickly while preserving the distinction between observation and inference.

The likely-cause section should use conditional language when evidence is incomplete, and the unknowns section should name checks the agent did not perform. Stable headings also make it easier to compare the response with tool records and reject an answer that omitted degraded state.
