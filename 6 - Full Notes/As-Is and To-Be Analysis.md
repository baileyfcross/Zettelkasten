# As-Is and To-Be Analysis

As-is and to-be analysis compares how an organization currently delivers services with the future state it intends to reach. The as-is view records existing applications, infrastructure, contracts, processes, risks, and responsibilities; the to-be view describes the desired cloud-enabled arrangement.

The gap between the views becomes migration work. Making both explicit prevents a cloud transition from being treated as a simple technical relocation when it also changes costs, controls, integration, and ownership.
