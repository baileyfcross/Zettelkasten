## Overview Chapter

### From source text to managed execution

C# development begins with a language whose source is compiled into intermediate language and executed by a managed .NET runtime. [[C Sharp Language and Type Fundamentals]] supplies the vocabulary for that process: declarations introduce named values, built-in numeric and Boolean types constrain the operations those values support, strings represent text, and type inference lets the compiler recover a static type without repeating it in the declaration. Nullable value types extend a value type with an absent state, while the nullable-reference analysis introduced for C# 8 makes the possibility of a missing reference visible to the compiler. These mechanisms are related by a single aim: make assumptions about data explicit enough that errors can be detected before or near the point where they arise.

Expressions turn those values into behavior. [[C Sharp Operators Flow and Conversion]] connects arithmetic, assignment, comparison, Boolean, bitwise, and shift operators to selection and repetition. `if` statements and pattern matching choose behavior from runtime conditions; switch expressions turn alternative patterns into values; loops repeat work while a condition or sequence supplies more input. Type conversion is another form of controlled transition. A cast asserts compatibility, conversion APIs deliberately change representations, and `TryParse` treats invalid external text as an expected branch rather than an exceptional crash. Checked arithmetic applies the same principle to numeric overflow by asking the runtime to report a result that cannot fit its destination type.

Once an operation deserves a name and boundary, it becomes part of [[C Sharp Functions Diagnostics and Testing]]. Parameters define the inputs a caller must or may provide, return values define what the function produces, and recursion lets a function express a problem in terms of smaller instances of itself. That abstraction is only dependable when its behavior can be observed. XML documentation records the public contract, debugger breakpoints allow a developer to pause and inspect state, and `Debug` and `Trace` output can be routed through listeners at useful levels. Unit tests then convert important examples and invariants into executable checks. Diagnostics explain what happened during an execution; tests state what should continue to happen as the implementation changes.

### Designing reusable types and libraries

Functions live within a broader model of reusable types. [[C Sharp Object-Oriented Type Design]] develops that model from classes and objects through fields, access modifiers, enumerations, constants, read-only state, constructors, overloaded methods, optional and named arguments, tuple returns, properties, and indexers. The key design question is not merely where syntax permits data to be stored, but which invariants a type promises to maintain. Private fields hide representation choices, constructors establish valid initial state, and properties expose controlled access. Overloads and optional arguments can make common calls concise, while named arguments and tuple deconstruction make the meaning of returned or supplied values more visible.

[[C Sharp Interfaces Generics and Inheritance]] expands reuse beyond one concrete type. A base class shares implementation and establishes an inheritance relationship; a derived class specializes or overrides that behavior. Interfaces instead state capabilities that unrelated types can implement, and default interface methods can evolve a contract with shared behavior. Generics preserve static type information while reusing algorithms and containers, structs provide value semantics for suitable small data shapes, and delegates represent callable behavior that events can publish to subscribers. Extension methods attach discoverable operations to an existing type without modifying it. These features solve different reuse problems, so a clear design chooses composition, contracts, parameterized types, or inheritance according to the relationship it needs rather than treating them as interchangeable.

Those types become deployable building blocks through [[.NET Assemblies Packages and Deployment]]. Compilation produces assemblies containing intermediate language, metadata, and resources; namespaces organize type names but do not themselves define deployment units. NuGet packages distribute one or more assemblies and their dependency metadata. The `dotnet` command-line interface restores, builds, tests, runs, and publishes projects across supported systems. A framework-dependent deployment relies on a compatible installed runtime, whereas a self-contained deployment carries the selected runtime with the application. .NET Standard historically defined a common API contract across .NET implementations, and portability analysis helps identify dependencies that cannot follow an application to its intended platform. These boundaries explain why source compatibility, runtime compatibility, and packaging are separate questions.

### Data in memory and at system boundaries

Applications manipulate values through the facilities organized by [[.NET Core Data Types and Collections]]. Specialized numeric types such as `BigInteger` and `Complex` extend ordinary arithmetic, while immutable strings and mutable `StringBuilder` instances support different patterns of text work. Regular expressions recognize structured patterns. Collection interfaces describe enumeration and mutation contracts, and concrete lists, dictionaries, stacks, queues, and sets encode different access and membership needs. Immutable collections protect shared snapshots; spans provide allocation-conscious views over contiguous memory; indexes and ranges describe positions and slices. Reflection reads assembly and type metadata at runtime, including developer-supplied attributes, while internationalization separates culture-sensitive formatting and comparison from fixed program logic. Garbage collection manages ordinary object memory, but it does not eliminate every resource-lifetime decision.

Persistent and transmitted data crosses another boundary in [[.NET Files Streams and Serialization]]. Portable code constructs paths through .NET APIs rather than hard-coded separators, then uses drive, directory, file, and metadata objects to inspect storage. A stream presents bytes independently of whether their source is a file, memory, or network. Readers and writers add text or XML interpretation, encodings map between characters and bytes, compression transforms the byte flow, and pipelines coordinate buffered producers and consumers. Deterministic disposal releases handles at the end of their intended scope. C# 8 asynchronous streams extend incremental processing to values that arrive over time. XML and JSON serialization map object-shaped data to external representations, but those representations are contracts: their schema, encoding, versioning, and trust assumptions must be designed rather than inferred from an in-memory object alone.

Data protection belongs to [[.NET Cryptography and Access Control]]. Symmetric encryption, including AES, protects confidentiality with a shared secret key, while an initialization vector ensures repeated encryption does not expose repeated beginnings in the same way. Cryptographic hashes such as SHA-256 produce fixed-size digests for integrity-oriented constructions, and random salts make equal passwords yield different derived values. Digital signatures join hashing with asymmetric keys to support origin and integrity verification. Keys, salts, nonces, and other security-sensitive values require a cryptographically secure random generator rather than the general-purpose `Random` class. These primitives support but do not replace identity policy: authentication establishes an identity, and authorization decides whether that identity's roles or claims permit a requested operation.

### Querying and persisting application data

[[Entity Framework Core Data Access]] maps .NET entities and relationships to a database through a provider and a bounded database context. Conventions infer common keys and relationships, data annotations supply local hints, and the Fluent API describes mappings that need greater precision or separation from entity classes. Seed data establishes stable known rows. Queries can load related data eagerly, explicitly, or lazily, with different visibility and round-trip costs. Change tracking records whether entities were added, modified, or deleted and turns a completed unit of work into commands when changes are saved. Transactions protect a coherent group of operations from partial completion. The abstraction reduces repetitive data-access code, but it does not erase the database: generated queries, provider differences, connection configuration, indexes, and transaction duration still determine real behavior.

The query vocabulary itself is developed in [[LINQ Query Construction]]. LINQ extension methods form pipelines for filtering, projection, ordering, type filtering, set operations, joins, grouping, and aggregation. Lambda expressions provide the predicates and selectors that customize those operators. With `IEnumerable<T>`, the operations execute as .NET delegates over objects; with `IQueryable<T>`, a provider examines expression trees and may translate them into SQL or another query language. That distinction makes deferred execution and provider capability important parts of correctness. Parallel LINQ can partition suitable in-memory work, while LINQ to XML applies the same compositional style to document construction and traversal. A good query expresses the smallest required result and respects where its computation will actually occur.

### Concurrency and asynchronous flow

Responsive and scalable programs coordinate work through [[.NET Task Parallelism and Asynchrony]]. A process owns execution resources, a thread is an operating-system execution path, and a task represents work or eventual completion at a higher level. Tasks may execute sequentially or concurrently, be awaited individually or in groups, continue from earlier results, and form explicit parent-child relationships. Concurrency also creates hazards: a race makes results depend on timing, a lock protects a critical section, inconsistent lock order can deadlock, and `Interlocked` operations provide atomic transitions for limited forms of shared state. `async` and `await` express nonblocking dependencies with readable control flow, while asynchronous streams yield a sequence one awaited item at a time. These tools improve responsiveness when work spends time waiting, but they do not make CPU computation free or shared mutable state safe by default.

### Building web applications and services

At the application boundary, [[ASP.NET Core Page and MVC Development]] organizes HTTP processing as a configurable middleware pipeline. Static-file and default-file middleware can satisfy public asset requests early; routing selects a Razor Page handler or an MVC controller action; dependency injection supplies services without binding request logic to their construction. Razor Pages pair a page-oriented model with a template and shared layout. MVC separates controllers, views, and models, with routes defining public URLs and action filters applying cross-cutting behavior around execution. Model binding converts untrusted request values into input objects, validation reports whether those values meet declared rules, and asynchronous actions yield while I/O completes. The framework's modularity makes pipeline order, public input shapes, and service lifetimes visible architectural choices.

[[ASP.NET Core Web API Development]] applies the same host to machine-facing HTTP contracts. Requests identify resources and operations through routes and methods such as GET, POST, PUT, and DELETE; responses use status codes and serialized transfer objects to communicate outcomes. Content negotiation selects a supported representation, problem details can make failures structured, and repositories can separate persistence coordination from controllers. OpenAPI describes operations and schemas in a machine-readable document, with Swagger tooling providing discovery and interactive exploration. `IHttpClientFactory` creates configured clients while managing reusable handlers for outbound calls. Cross-origin policy controls which browser origins may call a service, and health checks report whether operational dependencies are ready. An API is reliable when its runtime behavior, documentation, error semantics, and client assumptions describe the same contract.

Web content can also be managed through [[ASP.NET Core Content Management Systems]]. A CMS such as Piranha integrates editorial tools and content APIs into an ASP.NET Core application. Content types define sites, pages, posts, and other durable structures; fields and regions give their values meaning; reusable components allow constrained composition; and templates convert stored content into delivered pages. Slugs connect editorial identities to routes, media management organizes assets, and authentication plus authorization separates public delivery from editorial powers. Importing an existing database becomes a deliberate mapping and validation process rather than a one-off copy. The result illustrates a broader architectural principle: flexibility for editors is strongest when the system preserves an explicit content model underneath it.

### Learning systems and client applications

[[ML.NET Recommendation Applications]] shows how machine learning enters an ordinary .NET program as a lifecycle rather than a single algorithm call. Data is loaded into an `IDataView`, prepared into appropriate features and labels, divided so evaluation remains independent of training, and passed through a pipeline of transformations and estimators. Fitting produces a reusable transformer, evaluation compares its predictions with held-out outcomes, and deployment applies the same preparation and learned model to new data. Matrix factorization can learn latent representations from interactions such as customer-product co-purchases and rank unobserved pairs by score. That score supports recommendation ordering, but it is not automatically a probability, and no metric compensates for data that fails to represent the decision environment.

The ecosystem reaches platform-specific clients through [[.NET Windows Desktop Applications]]. Windows Forms and Windows Presentation Foundation gained support on .NET Core 3.0 for Windows, while the Windows Compatibility Pack helped port code that still required Windows-specific APIs. UWP used package identity, capabilities, adaptive layouts, and XAML to target the modern Windows device family. In XAML, markup constructs an object tree, markup extensions provide dynamic values, resources and templates centralize presentation, and data binding connects interface properties to changing application state. Fluent visual effects such as acrylic, motion, and reveal can reinforce hierarchy and feedback, but the application remains responsible for accessibility, performance, and a coherent model of interaction.

[[Xamarin.Forms Mobile Applications]] applies shared C# and XAML ideas to iOS and Android. A `ContentPage` contains a screen's controls; `Entry`, `Editor`, and `ListView` handle common input and collection displays; two-way binding transfers edits to a view model; and `INotifyPropertyChanged` tells the interface when source state changes. Navigation organizes pages into a mobile flow. Shared interfaces can request native capabilities through the dependency service, with each platform project supplying its own implementation, permissions, packaging, and startup code. HTTP services are consumed asynchronously so limited networks do not freeze the interface. Cross-platform reuse therefore comes from a carefully chosen boundary: domain logic and common presentation can be shared, while platform obligations remain explicit.

The transition from established Windows applications to the newer runtime belongs to [[Windows Desktop Modernization]]. Moving a Windows Forms or WPF application from .NET Framework to .NET Core 3 begins with an SDK-style Windows Desktop project and an audit of its APIs and dependencies. The Windows Compatibility Pack can preserve access to Windows-specific facilities where cross-platform replacement is neither practical nor intended. XAML Islands allow an existing desktop window to host selected UWP controls through `WindowsXamlHost`, providing incremental access to newer interface capabilities without requiring a complete rewrite. Publishing introduces further choices: resources must follow the application, a single-file executable can simplify distribution, and process-launch behavior must account for the deployed layout rather than assumptions inherited from a development machine.

At a larger operational boundary, [[Azure Cloud Application Development]] connects .NET code to managed cloud services. Cosmos DB stores distributed documents; Azure SignalR supports server-pushed client updates; Logic Apps and Functions coordinate workflows; and IdentityServer plus OAuth define token-based access. Blob and queue storage separate durable objects from asynchronous messages. Docker packages independently deployable services, AKS maintains replicated container workloads, and cognitive or bot services expose pretrained analysis and conversational channels. Each managed component reduces some infrastructure work while making the contract between code and platform—configuration, identity, message shape, retry behavior, and observability—part of application design.

Across these areas, C# and .NET development is a progression of boundaries. Static types bound the values a program can manipulate; functions and objects bound behavior and state; assemblies and packages bound distribution; streams and serializers bound external data; cryptography and authorization bound trust; contexts and queries bound persistence; tasks bound asynchronous work; and application frameworks bound requests, interfaces, and deployment targets. The ecosystem is most coherent when those boundaries carry clear contracts, observable failures, and tests appropriate to the layer they protect.
