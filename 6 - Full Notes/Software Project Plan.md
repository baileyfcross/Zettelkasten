# Software Project Plan

A software project plan records what a team currently believes it will build, how work and people will be organized, which resources are needed, how tasks will be estimated and scheduled, how risks will be handled, and how defects will be managed. In a plan-driven project it may be an approved document; in an agile project the team distributes much of the same planning across backlogs and iterations.

The plan should be treated as revisable. Software projects uncover requirements, dependencies, and technical difficulty while executing, so planning continues throughout the work instead of ending when an initial schedule is signed.
