# Non-Requirement

A non-requirement explicitly states behavior or scope that a product will not provide in the current release. It records a meaningful boundary where a stakeholder might otherwise infer that an omitted capability is included.

The list should not attempt to describe every impossible or excluded behavior. Its value is expectation management: documenting consequential exclusions, deferred features, and operational limits before a final demonstration prevents an unstated assumption from masquerading as an accepted requirement.
