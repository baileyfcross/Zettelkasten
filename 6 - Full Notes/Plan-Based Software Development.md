# Plan-Based Software Development

Plan-based software development defines phases, expected artifacts, dependencies, schedules, and completion criteria before much of the work is performed. Its forecasts are most credible when requirements and surrounding conditions are stable enough that later work will resemble what was anticipated.

The plan can coordinate resources and make obligations explicit, but it becomes fragile when uncertain requirements are treated as fixed facts. The source therefore treats a project plan as a rolling model that must be revised as evidence changes rather than as proof that the future is already known.
