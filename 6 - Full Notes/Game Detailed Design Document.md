# Game Detailed Design Document

A game detailed design document specifies parts, attributes, values, and behaviors precisely enough to implement. It records both the rationale for each part and an operational description that can become code or analog rules.

Quantities should use defined numbers, ranges, equations, or explicit unresolved issues rather than vague adjectives. Linked diagrams, mockups, prototypes, and spreadsheets keep the detail connected to the higher-level [[Game System Design Document|system]] and [[Game Concept Document|concept]] documents.

Detailed documentation is most reliable when it records knowledge demonstrated in the working game and names important unknowns. Writing speculative precision far ahead of implementation hides assumptions and makes the document expensive to maintain as the design emerges.
