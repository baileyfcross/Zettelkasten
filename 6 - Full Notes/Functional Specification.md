# Functional Specification

A functional specification describes what a program will do from the user's perspective. It can include an overview, usage scenarios, interface behavior, open issues, and significant non-requirements while avoiding internal data structures, algorithms, language choices, and other technical design details.

The document is a living statement of understanding rather than a claim that discovery has ended. An agile team may express the same function through [[User Story|user stories]], conversations, and acceptance criteria instead of one large document, but it still needs a reviewable account of intended behavior.
