# Feature Engineering

Parent topic: [[Machine Learning and Neural Networks]]

The construction, transformation, selection, and evaluation of representations that make raw data usable for analysis and machine learning.

## Overview Chapter

Feature engineering is the work of choosing how observations become variables that a learning system can use. It sits between raw data and modeling: the representation determines which regularities are visible, which comparisons are easy, and which distinctions may disappear. A [[Feature Engineering Foundations|foundational view]] begins with the feature itself—an attribute of a data object—and with the feature vector that collects attributes into a comparable form. Categorical, ordinal, and numerical variables carry different semantics, so their encodings should preserve meaningful relationships. One-hot encoding can remove a false numerical ordering from categories, while transformation, generation, and selection alter the space to make a task more tractable, accurate, or understandable.

The appropriate representation follows the structure of the source data. [[Text Feature Representation]] ranges from strings and edit distance to word sequences, bag-of-words counts, TF-IDF weights, phrases, structural descriptions, and latent semantics. Each level preserves something different: character similarity, token identity, local multiword context, document structure, or co-occurrence patterns. Sparse explicit features remain interpretable, while learned dense spaces can share statistical strength among related expressions. The decision is not merely about dimensionality; it defines what textual evidence a downstream model is permitted to recognize.

Images similarly support several kinds of [[Visual Feature Representation]]. Color histograms and moments provide compact global summaries, correlograms restore some spatial relationship, and co-occurrence matrices or Gabor filters expose texture. Shape context and histograms of oriented gradients describe form through relative geometry and local edge direction. Latent methods such as principal component analysis and Laplacian Eigenmaps instead derive coordinates from the observed image collection. Handcrafted descriptors state an intended invariance explicitly, whereas learned representations adapt to variation in the data and task.

Order creates additional representational choices. [[Time-Series Feature Engineering]] can characterize an entire series through distribution, stationarity, autocorrelation, entropy, or fitted-model behavior; summarize discriminative intervals; or recognize local shapelets and symbolic patterns. These features allow fixed-dimensional comparison among series of different lengths and can also describe where forecasting methods work well. [[Sequence Feature Engineering]] generalizes the pattern idea to ordered symbols and events. A sequence feature combines a pattern—such as a k-gram, closed pattern, or gap-constrained pattern—with a usage rule such as presence, cumulative count, position, or sliding-window activity. Separating the pattern from its mapping prevents mining frequency from being mistaken for the final representation.

Some environments make batch construction impossible. [[Streaming Feature Engineering]] addresses observations or dimensions that arrive over time when the complete input cannot be stored. Online principal components, matrix sketches, discriminant projections, manifold approximations, and kernel methods update representations incrementally. When features themselves stream in, selection methods must make sequential decisions about relevance and redundancy under unknown future dimensionality. Statistical controls such as alpha-investing illustrate how an online selector can manage accumulated false discoveries rather than treating every arrival independently.

Relations among objects require a graph-aware space. [[Graph Feature Engineering]] includes neighborhood counts, egonet structure, global position, and recursive aggregation of neighbor properties. Graph embeddings replace named measures with dense coordinates learned from network proximity. DeepWalk and node2vec use random-walk contexts, while GraRep factorizes relationships at several transition lengths. These methods do not preserve “the graph” in a universal sense; each objective selects a particular meaning of structural similarity, so the learning target should guide the representation.

Once candidates exist, [[Advanced Feature Selection]] controls irrelevance, redundancy, cost, and risk. Filters score data properties without repeatedly fitting a chosen model; wrappers evaluate subsets through model performance; embedded methods select as part of fitting. Search can be complete, sequential, randomized, or expressed through sparse optimization. Modern settings add requirements beyond accuracy: a subset may need to remain stable under resampling, reconcile multiple views, protect private statistics, or resist features that an adversary can manipulate. Selection is therefore a statement about operational constraints as well as predictive association.

[[Automated Feature Engineering]] turns construction into a guided search. Unary and binary transformations can be composed into a transformation graph whose nodes represent derived datasets. Expansion-reduction systems generate broadly and prune; evolutionary systems mutate and recombine candidate representations. Performance-guided traversal, reinforcement learning, distribution-based utility, and transformation recommenders allocate a limited evaluation budget. Automation expands the search that can be attempted, but its transformation vocabulary, validation design, and reward signal still encode human assumptions.

[[Pattern-Based Feature Engineering]] offers a structured version of construction. Frequent- or contrast-pattern mining defines candidate motifs, a selection phase controls redundancy and relevance, and a mapping function converts each match into binary, frequency, confidence, or growth values. The resulting pattern space can feed an ordinary classifier or become the basis of clustering. Keeping mining, selection, and mapping distinct is important: a common pattern is not automatically discriminative, and a useful pattern can behave differently under different value mappings.

Neural methods learn representations through training objectives rather than fixed formulas. [[Deep Feature Representation]] includes restricted Boltzmann machines, deep belief and Boltzmann networks, autoencoders, convolutional transfer, word embeddings, and variational autoencoders. Reconstruction, probabilistic modeling, contextual prediction, and supervised transfer each preserve different information. Bottlenecks, sparsity, corruption, and latent priors keep a learned feature space from becoming an uninformative copy. A deep representation is useful because of the constraints and evidence that formed it, not simply because it has several layers.

Application chapters show why domain structure remains indispensable. [[Social Bot Feature Engineering]] combines profile, friend, interaction-network, content, sentiment, and timing evidence because automation is behavioral and relational, not a single account flag. Holistic, pairwise, and egocentric detection choose different units of analysis, while Botometer demonstrates a broad operational feature system. [[Software Analytics Feature Engineering]] transforms code metrics, development history, change entropy, diffusion, commits, text, and developer activity into evidence for file-level or just-in-time defects, crash-prone releases, and turnover. Time-aware construction is essential so that future outcomes do not leak into present predictions.

Finally, [[Twitter Feature Engineering]] integrates short text, user profiles, structured metadata, media, and networks for platform-specific questions. Profile classification, crisis intent, and location estimation emphasize different subsets of those signals. Spatio-temporal-thematic analysis connects what is discussed with where and when activity occurs. Across every domain, the central lesson is consistent: a model sees only the distinctions its features make available. Effective feature engineering therefore combines data structure, task requirements, computational limits, and evaluation discipline into a representation whose strengths and omissions are explicit.
