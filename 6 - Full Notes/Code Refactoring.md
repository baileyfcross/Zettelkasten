# Code Refactoring

Code refactoring changes the internal structure of software to make it easier to understand and less expensive to modify without changing its observable behavior. Tests provide evidence that the cleanup preserved that behavior while names, functions, classes, or interfaces are reorganized.

Refactoring is most useful as regular maintenance around code already being understood and changed. It should be separated from a behavior change when possible so a failure can be attributed to either the structural transformation or the new requirement rather than an opaque mixture of both.
