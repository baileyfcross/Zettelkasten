# Fail-Safe Defaults

Fail-safe defaults deny access unless permission has been explicitly granted. When a decision or component fails, the system remains in a protected state instead of silently allowing an operation.

The principle reverses the burden of proof: authorization must be demonstrated. It is especially important when configurations are incomplete, errors occur, or new resources appear before policies are updated.
