# Structured Programming

Structured programming expresses control with nested sequence, selection, and iteration constructs whose boundaries remain visible in the program text. It reduces reliance on unrestricted jumps that can make the path to a statement depend on distant, difficult-to-follow transfers of control.

The approach supports top-down reasoning because a block can be understood as one step and later refined into smaller blocks. Its control structure is useful, but [[Modular Decomposition]] adds a different question: which design decisions should be hidden together so future changes remain local?
